# Maestro — 设计简报（重设计 round 2）

> ⚠️ 本文档是**中立简报**，不预设视觉风格。风格方向由每次生成的 direction prompt 给出。
> 上一版曾在此处硬性规定「AETHER 酸性赛博」，导致 17 个草稿全是同一种味道且被专业设计师否掉——
> 该约束已整体移除，**不要**从历史草稿继承霓虹/玻璃拟态/卡通怪兽的视觉语言。

---

## 1. 产品是什么

Maestro 是 **macOS 桌面音乐播放器**（Electron + React）。它不是网页、不是移动端、不是游戏。

它解决一个真实问题：用户的歌散落在四个平台（网易云、QQ 音乐、Deezer、Spotify），
每个平台的红心收藏互不相通。Maestro 把四个平台聚合成一个播放器：

1. **一次搜索，四平台结果聚合去重**
2. **红心 fan-out**：在 Maestro 里 ❤ 一首歌，会自动在其他平台找到同一首并同步收藏
3. **统一红心库**：跨平台合并后的一个列表（合并靠艺人/歌名归一算法，不是简单字符串相等）
4. **DeepSeek AI 推荐**：用户自带 API Key，基于统一库生成推荐
5. **本地优先**：所有凭据存本地，没有服务器

**产品气质**：这是一个给「歌听得多、且被平台割裂困扰」的人用的工具。
它的核心不是"好看的播放器"，是**把四个平台缝合起来这件事本身**。设计要让这件事被看见。

## 2. 真实数据边界（硬约束 · 上一版翻车的主因）

设计稿里出现的**每一个数字、标签、状态都必须来自下面这张表**。
上一版把歌曲时长换算成 "HP 3200"、把标题长度换算成 "ATK 847"，凭空造了一套战斗数值当主视觉——
这是最先被否掉的一点。**没有真实数据支撑的信息，不要画。**

### 真实存在、可以画的数据

| 数据 | 来源 | 说明 |
|---|---|---|
| 曲名 / 艺人 / 专辑名 | `Track` | 中英混排，长度不可控（要设计截断/换行策略） |
| 封面图 | `Track.cover` | 正方形，尺寸不定，可能加载失败（要有缺省态） |
| 当前时间 / 总时长 | 播放器 | `mm:ss` |
| 播放/暂停/加载中 | 播放器 | 三态，loading 是真实且常见的状态（跨平台取流慢） |
| 是否已 ❤ | `Track.liked` | 布尔 |
| **fan-out 同步数** | `fanOutCount` | **产品独有**：这首歌已同步到几个平台（0-4），会异步爬升 |
| 红心库总数 | `likedCount` | 跨平台合并去重后的总数 |
| 当前音源 | `provider` | qq / netease / deezer / spotify 四选一 |
| 音质档位 | `qqQuality` | 仅 QQ/网易云登录后可见 |
| 试听降级标记 | `trialFellBack` | 全曲拿不到、回落到 30s 试听 |
| 歌词 | `lyrics[]` | 有/无、逐行时间戳同步/不同步 两种，来源平台需标注 |
| 歌词来源 | `lyricsSource` | 歌词可能来自与音频**不同**的平台——这是真实且值得展示的信息 |
| 账号名 | `accountName` | 可能未登录 |
| AI 推荐条目 | `recoSuggestions[]` | 曲名 + 艺人 + 匹配度(0-100)。匹配度是模型给的，真实 |
| AI 库规模 | `recoLibrarySize` | 推荐所基于的曲库大小 |
| DeepSeek 是否配置 | `recoConfigured` | 未配置时是引导态，不是错误态 |

### 不存在、禁止编造

播放次数、听众数、波形图（无频谱数据源）、评分/星级、"相似度雷达"、
BPM/调性/能量值、战斗数值（HP/ATK/DEF/SPD）、等级/经验条、成就徽章、
好友动态、排行榜名次、任何形式的社交数据。

> 例外：如果某个视觉元素纯粹是**装饰**（背景纹理、色块、几何图形），可以存在——
> 但它不能**伪装成数据**（不能是没有数据源的图表、进度环、数值标签）。

## 3. 功能清单（一个都不能少）

重设计是换视觉语言，不是砍功能。下列元素必须在稿子里各自有明确位置：

**顶部窗口栏**（Electron 无边框窗，左上留 80px 给 macOS 红绿灯按钮，整条是拖拽区）
- 音源切换（四平台）· 搜索入口 · AI 推荐触发 · 红心库入口（带总数徽章）
- 音质切换（条件显示）· 登录/账号 · 设置 · 重置

**主区**
- 当前曲目：封面 + 曲名 + 艺人 + 专辑
- 歌词区：当前行高亮、前后行弱化；需能表达"无歌词"和"不同步"两种降级态；标注来源平台
- fan-out 同步状态：这首歌同步到了哪几个平台（产品的差异化功能，值得一个像样的位置）
- AI 推荐区：3 条推荐（曲名/艺人/匹配度）+ 未配置 Key 的引导态

**播放控制**
- 上一首 / 播放暂停 / 下一首 / ❤ 收藏 / ✕ 不喜欢
- 进度条（可拖拽 seek）+ 当前时间 + 总时长
- 音量

**状态表达**
- 加载中、试听降级、未登录、无歌词、AI 未配置——这些降级态很常见，必须有设计，不能只画理想态

## 4. 工艺底线（专业设计师会逐条挑的）

上一版被指出「间距/字重/对齐粗糙」。以下是硬性要求：

**排版**
- 建立**明确的字号阶梯**（建议 5-6 级，比例关系可辨，如 1.25 或 1.333），不要随手写字号
- 字重使用克制：全稿不超过 3 个字重；靠**字号/颜色/间距**建立层级，不靠加粗堆叠
- 数字（时间码、计数、百分比）用等宽字体，保证跳动时不抖动
- **中文排版**：界面是中文，中英混排要处理字重差异（中文字体视觉重量普遍高于西文），
  中文不要用 letter-spacing 拉字距，不要用全大写逻辑

**间距与网格**
- 用**一套间距标度**（4 或 8 的倍数），不出现 13px、17px 这种游离值
- 元素必须有**可见的对齐关系**：同组元素共享基线/边缘，不同组之间用留白分隔而不是描边分隔
- 光学对齐优先于数学对齐（图标与文字、圆形与方形并排时）

**颜色**
- 一个**克制的调色板**：中性色阶 + 最多 1-2 个强调色。强调色只用于状态和交互，不用于装饰
- 明确的对比度：正文对背景 ≥ 4.5:1，大字/次要文字 ≥ 3:1
- 深浅两套主题都要成立（应用有 light/dark 主题机制）

**层级与深度**
- 用**层级差异**（尺寸、留白、颜色）建立视觉重点，而不是靠描边和阴影把每个元素都框起来
- 阴影若使用，必须统一光源方向和一套标度；不要每个卡片一个随机阴影

## 5. 反模式（明确禁止）

上一版翻车的具体形态，以及同类陷阱：

1. **主题化换皮**：把播放器包装成游戏机/宇宙飞船/怪兽图鉴。装饰主题盖过了产品本身
2. **固定画布缩放**：上一版按 1440×900 画死再整体 `scale()`。这是桌面应用，
   **窗口可任意缩放**，布局必须是响应式的（用比例/弹性布局，不是绝对定位画布）
3. **AI 味视觉套装**：霓虹描边 + 玻璃拟态 + 深空渐变 + 粒子星尘 + 发光脉冲 + HUD 等宽标签，
   这套组合是当下 AI 生成设计的标志性特征，专业设计师一眼识别。**整套禁止**
4. **装饰性假数据**：见第 2 节
5. **表情符号当图标**：🔍 🎲 ❤ ⚙ 这类 emoji 直接当 UI 图标用（当前代码就是这样），
   跨平台渲染不一致且非常业余。用统一的线性图标集
6. **描边综合征**：每个元素都套一个 1px 边框 + 圆角 + 半透明背景，导致画面全是框、没有层级
7. **英文科幻标签**：TRACKING / SYNC STATUS / NEURAL FEED 这类词填充界面。
   界面是中文的，功能标签就用准确的中文

## 6. 技术边界

- **窗口**：macOS 无边框窗，可缩放。设计需在 1280×800 到 1920×1200 之间都成立
- **字体**：只用可自托管的开源字体或系统字体（应用离线可用，不依赖 CDN）
- **图标**：统一线性图标集（lucide 风格），内联 SVG，不引 CDN
- **动效**：克制。只用于状态转换和反馈，不用于吸引注意。必须响应 `prefers-reduced-motion`
- **封面取色**：应用已实现从封面提取主色写入 CSS 变量（`--cover-accent`），
  可以用作动态强调色——这是真实能力，鼓励使用
- **语言**：界面文案中文
