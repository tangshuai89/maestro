# Maestro Codebase Audit — Inconsistencies & Plan

> Date: 2026-07-30
> Scope: ~23k LOC across `packages/server`, `packages/renderer`, `packages/electron`
> Method: Read every TS/TSX file (104 files), every spec under `specs/`, all configs, CI, `.gitignore`, and `.env.example`. Verified critical claims against source.

## 🔴 P0 — Shipping blockers / data loss / auth bypass

| #   | Issue                                                                                                                                                                                                                                                                                                                                                                       | Location                                                                     |
| --- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------- |
| 0.1 | **Missing `protocols` in electron-builder** → packaged `.app` never registers `maestro://` URL scheme → Spotify OAuth is **broken in production**. Runtime `setAsDefaultProtocolClient` is a no-op in packaged builds; needs `CFBundleURLTypes` from `build.protocols`                                                                                                            | `packages/electron/package.json`                                             |
| 0.2 | **No single-instance lock** + no `second-instance` handler → if user re-clicks dock while first instance is starting, Spotify deep-link lands in the *second* process's private `oauthBuffer`; original renderer never sees it                                                                                                                                            | `packages/electron/src/main.ts:631-713`                                      |
| 0.3 | **`reconcileLiked` can wipe local ❤ on transient empty result** — `getLikedSet` returns `new Set()` (truthy) when upstream returns `[]` for "shape changed" reasons; the guard at line 1519 only protects when local is also empty. If user has any local liked and a transient fetch returns `[]`, **their entire ❤ list is silently overwritten**                                                                                | `packages/server/src/music/music.service.ts:1503-1572`                        |
| 0.4 | **Backup files saved in plaintext on disk** containing all platform cookies + Spotify refresh token + DeepSeek API key. Controller exposes `GET /storage/state` (full state) with no auth check                                                                                                                                                                          | `packages/server/src/common/backup/backup.controller.ts:53-56, 99-117`        |
| 0.5 | **Backup passphrase has ~20 bits entropy**, not the documented ~42 — comment says `crypto.getRandomValues`, code uses `Math.random`. README and UI say "strong passphrase"; they're wrong                                                                                                                                                                                   | `packages/renderer/src/lib/backup-crypto.ts`                                 |
| 0.6 | **QQ login window race** — between A's `runLoginWindow` start and `__maestroLastResult` being set, B's click spawns a new BrowserWindow. A's window is orphaned (kept alive by `keepAliveAfterSuccess=true`), and the second `'closed'` listener attaches to B only                                                                                                       | `packages/electron/src/main.ts:384-444`                                      |
| 0.7 | **`typeof typeof window` typo** in `useAuth.ts:23` — first `typeof` always returns a string, so the check is always truthy. Harmless here (next `window` access still crashes in non-browser envs), but dead code in a security-critical file                                                                                                                                  | `packages/renderer/src/hooks/useAuth.ts:23`                                  |
| 0.8 | **NetEase cookie-fallback login is unreachable** — `showCookieFallback` is hardcoded `false` (line 485), and `setShowCookieFallbackExternalRef.current` is never assigned. The whole "browser-fallback" code path is a no-op                                                                                                                                                 | `packages/renderer/src/hooks/useAuth.ts:213-216, 485, 521-526`               |

## 🟠 P1 — Security holes (no auth), significant race conditions

| #   | Issue                                                                                                                                                                                                                                                                                                | Location                                                                                  |
| --- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------- |
| 1.1 | **All HTTP endpoints lack auth/CSRF** — `POST /auth/spotify/client-id`, `POST /reco/key`, `POST /storage/import`, `POST /music/like/merged`, `GET /auth/logout` are all state-changing and reachable by any localhost process. `enableCors({credentials:true})` makes this worse               | `auth.controller.ts`, `reco.controller.ts`, `backup.controller.ts`, `music.controller.ts` |
| 1.2 | **Wildcard `on/removeListener` IPC bridge** — preload exposes `electronAPI.on(event, cb)` with no whitelist; renderer XSS could subscribe to any future `deeplink-secret`/`oauth-payload` channel                                                                                                  | `packages/electron/src/preload.ts:108-113`                                                |
| 1.3 | **`setWindowOpenHandler` allows ALL URLs** in both main and login windows — any `<a target=_blank>` on `*.qq.com` or `music.163.com` opens an Electron window that shares the user's session cookies                                                                                          | `main.ts:297-299`, `login-window-runner.ts:181`                                          |
| 1.4 | **Cookie domain match uses `String.includes` substring** — `attacker-y.qq.com` matches `.y.qq.com` filter; lookalike domains can poison the cookie capture                                                                                                                                       | `login-window-runner.ts:202`                                                              |
| 1.5 | **`oauthBuffer.consume()` is single-consumer** — concurrent consumers (e.g. React Strict Mode) overwrite `this.consumer`; first caller's Promise **leaks forever**                                                                                                                                | `electron/src/auth/oauth-buffer.ts:51-83`                                                 |
| 1.6 | **`like`/`dislike` race in `usePlayer`** — single-provider paths use `provider` instead of `track.provider`; after async switch, mutations apply to the wrong track. `toggleLike` and `dislike` have **no try/catch**; rejections become unhandled                                                | `usePlayer.ts:977-1101`                                                                   |
| 1.7 | **Radio loading has no request epoch** — rapid skip / provider change / Strict Mode can let an old response replace a newer track and clear its loading state                                                                                                                                     | `usePlayer.ts:608-665`                                                                   |
| 1.8 | **Spotify WPS volume disconnect** — `VolumeControl` only mutates `HTMLAudioElement.volume`. On Premium WPS path, volume UI does **nothing** but the slider claims it does                                                                                                                       | `VolumeControl.tsx`, `useSpotifyWpsPlayer.ts` (no volume method)                          |
| 1.9 | **`refresh-coordinator.run<T>` uses unsafe casts** (`as Promise<T>`, `as Promise<string|null>`) — the generic is fictional; the Map is hard-typed. Could lead to type-vs-runtime drift                                                                                                          | `auth/refresh-coordinator.ts:32, 40`                                                     |
| 1.10| **WPS end-of-track not consumed** — Spotify Premium queue never advances when WPS finishes a song; transport stays "playing" with no audio                                                                                                                                                        | `useSpotifyWpsPlayer.ts`, `usePlayer.ts`                                                 |
| 1.11| **All dialogs lack focus trap / `role=dialog` / Escape handling / focus restoration** — keyboard users can tab into background controls; screen readers don't get modal semantics. Affects every modal                                                                                          | `Modal.tsx:18-24`                                                                        |
| 1.12| **`ProgressBar` is a click-only `<div>`** — no slider semantics, not focusable, no keyboard nav, no ARIA value attributes                                                                                                                                                                          | `ProgressBar.tsx:27-37`                                                                  |

## 📋 Proposed work groups (pick any combination)

Each item below is **scoped to 1–3 days** and can be done independently. Each ends with `npm run typecheck && npm test` passing.

### Group A — **Shipping blockers** (~2–3 days)

- **A1** Fix `protocols` + single-instance lock + deep-link `?error=` handling (resolves 0.1, 0.2)
- **A2** Fix `reconcileLiked` empty-set guard (0.3)
- **A3** Encrypt backup at rest OR remove plaintext backup option entirely (0.4) + add auth check on `GET /storage/state`
- **A4** Use `crypto.getRandomValues` for backup passphrase + remove misleading UI claims (0.5)
- **A5** Fix QQ login window race (0.6)
- **A6** Fix `typeof typeof` typo + restore NetEase cookie-fallback (0.7, 0.8)

### Group B — **Auth & security hardening** (~2–3 days)

- **B1** Add loopback-only / shared-secret guard on all state-changing endpoints (1.1)
- **B2** Whitelist IPC channels in preload + `setWindowOpenHandler` (1.2, 1.3)
- **B3** Fix cookie domain suffix matching (1.4)
- **B4** Make `oauthBuffer.consume()` a FIFO queue (1.5)
- **B5** Audit/refactor login-window-runner.ts + add tests for the race + lookalike scenarios

### Group C — **Player stability** (~2–3 days)

- **C1** Fix like/dislike race + add try/catch + ensure correct `track.provider` (1.6)
- **C2** Add request epoch / AbortController to radio load + retry timers (1.7, plus timer cleanup)
- **C3** Wire WPS volume + WPS end-of-track → queue advance + disconnect recovery (1.8, 1.10)
- **C4** Add `<dialog>` semantics + focus trap to `Modal` (1.11)
- **C5** Replace `ProgressBar` click-div with a native `<input type=range>` (1.12)
- **C6** Renderer test scaffolding + tests for reducer, usePlayer happy paths (2.20, 2.21)

### Group D — **Spec & architecture cleanup** (~2 days, low-risk)

- **D1** Update stale specs: unified-search, match-engine, library-import, heart-fanout (2.1, 2.2, 2.5)
- **D2** Fix spotify spec v2 acceptance (deprecated endpoint) + reco 412→428 (2.3, 2.4)
- **D3** Move `Track` from `music.service.ts` to `music/types.ts`; remove `as never`; clean unsafe casts (2.6, 2.7, 1.9)
- **D4** Write specs for lyrics, backup, audio/cover proxy, like-sync internals (2.10)
- **D5** Write specs for NEXT-ITERATION W2–W5 before any new feature code (2.11)

### Group E — **Build, test, dev-tooling** (~2–3 days)

- **E1** Lock Electron with `integrity`; bump Electron 31 → 35+ if CastLabs tracks it (2.13)
- **E2** Add `*.tsbuildinfo` to .gitignore; fix `tsc -b` no-op; enable `forceConsistentCasingInFileNames` (2.14, 2.17, 2.26)
- **E3** Reconcile README / vite.config / ConfigService ports & `/api` claim (2.15, 2.16)
- **E4** Enable `react-hooks/exhaustive-deps`; add ESLint to server + electron (2.18, 2.19)
- **E5** CI: add `npm run build` + macOS runner + castLabs EVS VMP smoke (2.25)
- **E6** Add husky + commitlint + prettier + .editorconfig + `engines` (2.23)
- **E7** Tighten claude.yml: remove `id-token: write`, add allow-list, add concurrency (2.24)
- **E8** Add provider tests for NetEase + Deezer (minimal happy-path coverage) (2.22)
- **E9** Update README description + add LICENSE + fix package metadata (2.27)
