# 歌单导出（.txt）

## 做什么

App 有**整库**的加密备份导出，但没有「**把这张歌单发给别人**」——
功能盘点 P3（成本 1 天）：`歌单分享 / 导出 · sharePlaylist / 导出歌单 → 0 处`。

## 现状（实测，master `0bb5860`）

`grep -rn "sharePlaylist\|导出歌单" packages/` → **0 处** ⇒ 纯新增。

## 关键设计

### 导成什么格式：**纯文本 .txt**，不是 JSON

这份文件的用途是**发给朋友**。对方拿到应该是一份「歌名 — 歌手」的清单，
能直接贴进任何播放器。JSON 里的 `platform:trackId` 对**没有同一个平台账号**
的人毫无意义。

（机器可读 / 可回导的 JSON 是另一件事 —— 要闭环得服务端补一个 import 端点，
不在本 spec 范围。）

### 纯函数与 DOM 副作用分开

- `buildPlaylistText(playlist, now?)` —— **纯函数**（歌单 → 文本），好测
- `downloadPlaylistText(playlist)` —— DOM 副作用（Blob + `<a download>`）

下载做法跟 `lib/lyricsShare.ts` 的歌词图片导出同款（浏览器原生下载），
Electron 里落到系统「下载」目录，**不引第三方库**。

### 格式细节

```
通勤路上（12 首）
导出时间：2026-10-26 11:30

1. Drip Dry Eyes — YUKIHIRO TAKAHASHI（5:30）
2. 晴天 — 周杰伦（4:29）
```

- 分隔符用 **`—`（破折号）而不是 `-`**：歌名/歌手本身可能带连字符
  （`A-B — C-D`），用 `-` 会被误读成分隔符。
- 时长为 0 → 不带时长括号（不出现「（0:00）」这种噪音）。
- 文件名去掉 `/ \ : * ? " < > |`（文件系统不允许），全空时兜底「歌单」，
  超长截断到 60 字。

### 入口

歌单管理弹窗（`PlaylistManagerModal`，#129 落的）底部「+ 添加歌曲」旁边加
「导出」按钮；**空歌单时禁用**。

## 局限（如实说明）

- **只导 .txt，不导 JSON** —— 见上（JSON 的回导闭环要服务端配合）。
- 导出的清单**不包含流地址/凭据** —— 只是一份「歌名 — 歌手」的对照表，
  对方自己按歌名搜即可（这是刻意的：导出文件里不该带任何指向本机账号的东西）。
- 不做「生成分享链接」—— 本地应用没有可分享的公网地址，做了也是假的。
