# 搜索历史

## 做什么

用户搜过的词**找不回来** —— 搜索框每次都是空的，重度用户只能凭记忆再敲一遍。

功能盘点 P2（成本 0.5 天）：`搜索历史 · searchHistory → 0 处`。

## 现状（实测，master `0bb5860`）

`grep -rn "searchHistory\|搜索历史" packages/` → **0 处**（前后端都没有）⇒ 纯新增。

## 关键设计

### 存在哪：localStorage（不是服务端）

搜索词是「本机使用痕迹」，**不是用户资产**：

- 不需要跟 ❤ 库 / 歌单一样按 session 分片落到 `state.json`
- 也不该进跨设备同步的语义里

走 `STORAGE_KEYS.searchHistory` ⇒ 顺带被**加密备份**自动带走
（`collectLocalStorage()` 遍历 `STORAGE_KEYS`）—— 不额外写导出逻辑。

### 规整规则（`lib/searchHistory.ts`，纯函数）

| 规则                    | 理由                                                                    |
| ----------------------- | ----------------------------------------------------------------------- |
| 去空白                  | 用户输入常带空格                                                        |
| 不记空串                | 空输入不是一次搜索                                                      |
| 同词去重 → **移到最前** | 追加第二条会让列表全是重复                                              |
| 最多 12 条              | 超了丢最旧的                                                            |
| 单条 ≤ 120 字           | 超长的是误粘贴/噪声                                                     |
| 读时过滤脏数据          | localStorage 用户能手改、备份导入也能塞；解析失败**绝不能**让搜索面板崩 |

### 什么时候记

**debounce 触发的那一刻**（用户「停下来打字」= 一次真实搜索意图）。
不是每次 `onChange` —— 那会把「周杰」「周杰伦晴天」这种中间态全记进去。

### UI

只在「**输入框是空的、还没搜**」时出现（搜出结果后它就该让位给结果）：

- 一排胶囊标签（`.sp-history-item`）
- 点一条 → 填回输入框 → 走正常 debounce 搜索
- 右上角「清空」

## 验收标准

- [ ] 搜过一次后清空输入框 → 出现「最近搜索」列表
- [ ] 点历史条目 → 填回输入框并触发搜索
- [ ] 「清空」→ 列表消失 + localStorage 也清掉
- [ ] 同一个词再搜 → 列表里**还是一条**（去重 + 移到最前）
- [ ] 脏数据（坏 JSON / 非数组 / 空串 / 非字符串 / 超长）→ 读出来是干净的，不崩
- [ ] localStorage 被禁用（private mode）→ 不影响搜索功能
- [ ] 存储键进 `STORAGE_KEYS` ⇒ 自动进加密备份
- [ ] 单测：`lib/searchHistory.test.tsx`（规整 / 并入 / 解析脏数据）+
      `SearchPanel.test.tsx` 补 4 条（显示 / 点击回填 / 清空 / 去重）
- [ ] `npm run typecheck && npm run lint && npm test` 全绿
- [ ] 覆盖率 diff 门禁绿
- [ ] 变异验证：把 `pushSearchHistory` 的去重去掉 → 门禁必须红

## 局限（如实说明）

- **只记歌曲 tab 的搜索**（专辑 tab 的搜索在 `AlbumResults` 里自己跑，不进历史）
  —— 两个 tab 共用同一个 `q`，混在一起会互相污染。
- 历史是**单机**的：换设备/清 localStorage 就没了（这是有意的，见「存在哪」）。
- 不做「搜索建议/联想」——那是另一件事（要调搜索接口做前缀匹配）。
