# 歌单编辑（Playlist Edit）

> **状态**：🚧 进行中 · 来源：产品盘点「该有的」P1「歌单编辑」
> 关联：`specs/nl-playlist/`（数据模型 + API）· `specs/remote-playlist/`（远端歌单读取）

## 背景与现状核实

**产品层的问题**：用户现在能建歌单、能删歌单，但**建完就没法管**。

现状核实（2026-10-25，代码逐行核对，不是凭印象）：

| 层          | 状态              | 证据                                                                                                                                                                                                                           |
| ----------- | ----------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| **后端**    | ✅ 全能           | `packages/server/src/library/playlist.service.ts:149` `patch(id, {name?, append?, remove?})`；改名 / 追加 / 移除全部实现且有测试                                                                                               |
| **接口层**  | ✅ 全能           | `packages/renderer/src/api.ts:361` `patchPlaylist(id, {name?, append?, remove?})`                                                                                                                                              |
| **hook 层** | ✅ 全能           | `packages/renderer/src/hooks/usePlaylist.ts:81/92/103` `rename` / `append` / `remove`，`usePlaylist.test.tsx` 已覆盖                                                                                                           |
| **UI 层**   | ❌ **只有建和删** | `packages/renderer/src/components/modals/NLPlaylistModal.tsx` —— 全文只出现 `pl.playlists`（第 306 行渲染列表）和 `pl.remove_playlist`（第 317 行删除按钮）。**`rename` / `append` / `remove` 三个方法在 UI 里一次都没被调用** |

> ⚠️ **修正上一轮盘点的说法**：盘点时写的是「后端有能力 UI 0 调用」——**不准确**。
> 中间隔着一层**能力齐备且有测试的 hook**。缺口精确地落在**UI 组件**这一层。
> 补 UI 即可，**不需要动后端、不需要动 hook**。

**用户可见症状**：在「我的歌单」里只能看到 `歌单名（首数）` 和一个「删除」按钮。点歌单名 = 播放。**看不到里面有哪些歌、改不了名、加不了歌、删不了单首歌**。

## 产品概念

**「建完能管」** —— 歌单是一个**容器**，不是一个终态。用户对容器的期待是：能打开看、能改名、能往里放东西、能拿出东西。

三条设计决定：

1. **不新造数据通路**：复用已有 `PATCH /library/playlists/:id`（`name` / `append` / `remove`）。
   本 spec **零后端改动**——如果发现后端不够，说明上一轮盘点漏了，要单独立项。
2. **管理 = 一个专门的弹窗**，不把编辑塞进 NL 弹窗里。NL 弹窗是「生成器」，
   管理弹窗是「容器」——两个心智模型混在一个 Dialog 里会互相干扰。
3. **改动走 hook 的乐观更新**（`usePlaylist` 已实现），失败时 hook 抛错、
   组件显示错误条、**列表回滚到服务端状态**（不假装成功）。

## 范围

### 做

1. **歌单管理弹窗**（新组件 `PlaylistManagerModal.tsx`）

## UI 规格

### 入口（`NLPlaylistModal`「我的歌单」区）

```
┌────────────────────────────────────────────┐
│ 我的歌单                        [刷新]      │
│ ┌────────────────────────────────────────┐ │
│ │ NL 2026-10-25（12）  [管理] [删除]     │ │
│ └────────────────────────────────────────┘ │
└────────────────────────────────────────────┘
```

- 「管理」→ 打开 `PlaylistManagerModal`（**不改变**「点歌单名 = 播放」这个既有行为）
- 「删除」→ 保持现状（`pl.remove_playlist`）

### 管理弹窗

```
┌─ 歌单管理 ──────────────────────────────┐
│ ✎ 夜跑 Electron 2026-10-25          [×] │  ← 标题行（点 ✎ 变输入框）
├──────────────────────────────────────────┤
│ 1.  Lose Control — Peggy Gou      3:42  × │  ← 点 × 移除该首
│ 2.  Ghost — Nia Archive          3:29  × │
│ ...                                      │
├──────────────────────────────────────────┤
│ [▶ 播放全部]              [+ 添加歌曲]    │
└──────────────────────────────────────────┘
```

**添加歌曲**（点开后在本弹窗内展开，不跳走）：

```
│ 🔍 [搜索歌名或歌手…]                        │
│ ┌────────────────────────────────────────┐ │
│ │ 1.  Animal —  Kygo             [+ 加]   │ │
│ │ 2.  Potion —  Zedd              [+ 加]   │ │
│ └────────────────────────────────────────┘ │
```

- 已在本歌单里的搜索结果 → 按钮显示「已在歌单」且**禁用**（避免用户点了没反应）
- 搜索复用 `searchUnified(q)`（跨平台统一搜索），只取 `track` tab

## 验收标准

每条都要有对应的自动化用例（`PlaylistManagerModal.test.tsx`）。

| #   | 标准                        | 判据                                                                                |
| --- | --------------------------- | ----------------------------------------------------------------------------------- |
| 1   | 点「管理」→ 打开弹窗        | 弹窗可见，标题 = 歌单名                                                             |
| 2   | 弹窗显示曲目列表            | 序号 / 标题 / 艺术家 与歌单数据一致                                                 |
| 3   | 改名：`Enter` 提交          | 调用 `patchPlaylist(id, {name})`，列表里歌单名同步更新                              |
| 4   | 改名：`Esc` 取消            | **不发起请求**，标题恢复原名                                                        |
| 5   | 改名失败（空名 / 超 60 字） | 错误条提示，**名称不改变**（不乐观更新）                                            |
| 6   | 移除单首                    | 调用 `patchPlaylist(id, {remove:[id]})`，该首从列表消失                             |
| 7   | 移除失败                    | 错误条提示，**该首仍在列表**（回滚）                                                |
| 8   | 添加歌曲                    | 调用 `patchPlaylist(id, {append:[item]})`，曲目数 +1                                |
| 9   | 添加重复的歌                | **服务端去重**（`playlist.service.ts:170` 按 id + sources[0] 去重）→ 曲目数**不变** |
| 10  | 搜索结果里已在歌单的歌      | 按钮禁用 + 显示「已在歌单」                                                         |
| 11  | 「播放全部」                | 调 `onPlay(tracks, 0)`                                                              |
| 12  | 0 首歌单                    | 显示空态文案                                                                        |
| 13  | 关闭后重开                  | 显示最新状态（hook 状态已是最新）                                                   |
| 14  | 服务端 `PATCH` 整体失败     | 错误条显示服务端原文，不静默                                                        |

## 技术约束

- 前端状态用 React hooks（**不引 Redux**）
- 类型放各自模块（`Playlist` 已在 `packages/renderer/src/api.ts:327`，
  **不重复定义**；新组件直接 import）
- 组件用仓库既有的 shadcn `Dialog` / `Button` / `Input`（`components/ui/`）
  —— 沿用 `NLPlaylistModal` 的写法，**不引新 UI 库**
- 命名空间严守 `sh-` 前缀（见 `specs/shadcn-migration/spec.md`）
- 外部调用统一走 `packages/renderer/src/api.ts` 的 `fetchWithToken`
  （**不新增 fetch 点**）
- renderer 的测试文件**必须 `.test.tsx`**（`.test.ts` 会被 `scripts/test.sh`
  的 ts-node 管道接手 → 整个套件红）
